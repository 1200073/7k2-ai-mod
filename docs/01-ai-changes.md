# 五刀 AI 改造 —— 改了什么、为什么、效果如何

> 所有改动都在 `src/ai.cpp`。
> 全部通过 **hook 引擎函数**（不修改 `7K2.exe`），带**字节指纹校验**，校验不过就跳过。

---

## 一刀：魔族会开矿

### 原版的病

```c
// Unit::ai_build_firm() 第一行
if( nation_res[nationRecno]->race_id != race_id )
    return 0;    // ★ 国家种族 ≠ 单位种族 ⇒ 直接拒绝
```

**⇒ 魔族国家想造人类建筑（矿场、兵营、酒馆）时被永久拒绝。**

⇒ 没有矿场 = 没有稳定收入 ⇒ 发展链断在第一环。

### 我们的改法

Hook `Nation::ai_should_build_mine`（`0x41EDD0`）：

```c
if( 是魔族 && 有城镇 )  return 1;   // 放行
```

**但加了三个约束，避免"一上来就乱建"：**

| 约束 | 原因 |
|---|---|
| 排除牛头人（`MONSTER_MINOTAUROS`） | 它走"炼金术"路线，不需要矿 |
| 必须有城镇（`ai_town_count > 0`） | 否则开局就开矿，破坏平衡 |
| **每国 30 个游戏日冷却** | 否则 3 个城会同时开 3 个矿 |

> ⚠️ 冷却最初用的是 `GetTickCount()`（真实时间），**后来改成 `info.game_date`** —— 因为真实时间会让联机不同步。见 [`04-multiplayer.md`](04-multiplayer.md)。

### 效果

玩家实测："**魔族会开矿了**"

## 二刀：魔族扩军 / 造堡垒

### 原版的病

同一个种族检查拦住了 `ai_should_expand_military`。

**⇒ 魔族不造堡垒 ⇒ 没有将军位 ⇒ 带不了兵 ⇒ 也不会造更多东西。**

这是**连锁反应**：一个检查断掉整条发展链。

### 我们的改法

Hook `Nation::ai_should_expand_military`（`0x426AF0`）：

```c
if( 是魔族 && 有城镇 && 无兵营 )  return 1;
```

**关键：我们只负责"批准"，具体的选址、下命令还是原版的 `think_military` 做** ——
这样风险最低（不自己调 `find_best_place_loc` / `add_action`）。

### 效果

玩家实测："**建堡垒开矿了**"

## 三刀：叛乱者不再无脑送死

### 原版的病

```c
// Rebel::think_new_action()
switch( misc.random(3) )
{
    case 0: 攻城;      // ★ 2 个叛军也会去攻城
    case 1: 打建筑;
    case 2: 建新城;
}
```

**⇒ 决策完全不看实力。** 2 个叛军跑去打有重兵驻守的城堡，纯送死。

### 我们的改法

Hook `Rebel::think_new_action`（`0x563390`），按**兵力分级**：

| 兵力 | 行为 |
|---|---|
| **≤ 2（弱队）** | 45% 建新城，否则迁移 —— **绝不攻城** |
| **3 ~ 7（中队）** | 35% 迁移 / 35% 打建筑 / 30% 建新城 |
| **≥ 8（强队）** | 交还原版三选一 |

**每档都带失败回退链** —— 上一步失败就试下一步，不会僵住。

### 效果

玩家实测："**更聪明机动、会建中立城**"

## 四刀：叛军血量 ×2

### 为什么不能 hook

`Unit::max_hit_points()` **是头文件内联函数** ——
exe 里**没有独立入口**，没有地址可 hook。

### 我们的改法

**改它算的那个字段。**

```c
// Skill 是 pack(1)，15 字节，skill 在 Unit+0x7B
// 其中 std_hit_points 在 Unit+0x80（short）
*(short*)( (char*)unit + 0x80 ) *= 2;
```

**⇒ 数据胜过代码。** 引擎之后每次算最大血量都自动翻倍。

**幂等保护**：记下原值，已翻倍就跳过（避免反复调用变成 ×4、×8）。

### 效果

玩家实测：`stdHP 200 -> 400`，实际血条变长

## 五刀：清剿叛军不再自毁

### 原版的病（这是本项目的起因）

```c
// NationBase::civilian_killed(race, isAttacker, killedCount)  onationb.cpp:1867
if( isAttacker )
{
    change_all_people_loyalty( -2 * killedCount, civilianRaceId );   // ★★★ 全国忠诚 -2/人
    if( civilianRaceId == 0 )
        change_reputation( -10 * killedCount );    // 商队
    else
        change_reputation(  -1 * killedCount );    // 平民 / 叛乱者
}
```

**⇒ 叛乱者被当作"平民"结算** ⇒ 每杀一个叛军：声誉 **-1** ＋ **同民族忠诚 -2**。

### 死亡螺旋

```
杀叛军 → 全民族忠诚 -2/人 → 更多城镇跌破 REBEL_LOYALTY(29)
      → Town::think_rebel 又造一波叛军 → 还得杀 → 又 -2 → …
```

**⇒ 只把声誉改小甚至改成 0，螺旋照样转** ⇒ **必须同时切断"忠诚 -2"。**

### 我们的改法（两处 hook + 一个全局标记）

```c
// ① Unit::update_being_killed_statistic (0x5E3440) 入口
if( 死者是叛军 )  g_inRebelKill = 1;

// ② NationBase::civilian_killed (0x540AF0) 入口
if( isAttacker && g_inRebelKill )
{
    change_reputation( -0.3f * killedCount );   // 声誉只掉 0.3/人
    return;                                      // ★ 跳过原函数 ⇒ 忠诚完全不动
}
```

**⇒ 人族互杀 / 杀商队 / 杀普通平民 —— 全部走原路径，零影响。**

### 效果

玩家实测："**天才，忠诚度不掉了只掉声誉**"

## 改动一览表

| 刀 | Hook 地址 | 风险等级 | 联机安全 |
|---|---|---|---|
| 魔族开矿 | `0x41EDD0` | 低（改返回值） | ✅ |
| 魔族扩军 | `0x426AF0` | 低（改返回值） | ✅ |
| 叛军 AI | `0x563390` | 中（重写决策逻辑） | ✅（用同步随机） |
| 叛军血量 | 无 hook（改字段） | 极低 | ✅ |
| 叛军惩罚 | `0x5E3440` + `0x540AF0` | 中（跳原函数） | ✅ |
| 日期 | 无（改数据文件） | 极低 | ✅ |

**"风险等级"的判断标准**：

- **改返回值** = 最低（不改变调用结构）
- **改字段** = 最低（数据比代码安全）
- **重写逻辑** = 中（要保持原函数的副作用）
- **跳过原函数** = 中（要确认漏掉的东西不会别处需要）

## 代码在哪

全部在 [`src/ai.cpp`](../src/ai.cpp)（约 57 KB）。

每个 hook 都有：

1. **字节指纹校验**（不过就跳过，绝不盲调）
2. **日志**（首次命中才打，避免刷屏）
3. **开关**（`render.ini` 里可单独关）
