# 联机（局域网）与 AI 补丁

## 一句话

**可以联机**，前提是两台机器装**同一份补丁**（同 zip、同 `.asi` sha256、同 `render.ini` 开关）。

---

## 为什么能联机：AI 随机走同步种子

7K2 是 1999 年的 lockstep RTS —— **只有玩家指令在网络上传，AI 在每台机器本地各自跑**。
所以"两端 AI 必须产生完全相同的结果"，否则就会不同步。

源码里的关键证据（`oai_main.cpp`）：

```c
LOG_MSG(misc.get_random_seed());    // ★ 大量出现在 AI 模块的各个分支
```

**这是 RTS 的标准做法** —— AI 只用同步种子产生的随机数，作者把种子写进日志就是为了联机排错。

**⇒ 只要两端代码一样、种子一样，AI 行为就一样。**

顺带一个佐证：`Info` 结构里就有 `random_seed` 字段，说明种子是**游戏状态的一部分**，会随存档/联机同步。

---

## 曾经的真风险（已修）

我自己写的"魔族开矿 120 秒冷却"用了真实时间：

```c
- const DWORD now  = GetTickCount();     // ❌ 两台机器的毫秒数永远不同
- if (now - lastMineTime < 120000) return;
```

**⇒ 冷却边界处可能一边通过、一边不通过 ⇒ AI 决策分歧 ⇒ 经典不同步。**

**改法**：

```c
+ const int today = GameDateNow();      // ✅ info.game_date = 0x0068E334
+ if (today - lastMineDay < 30) return; //    30 个游戏日
```

**⇒ `info.game_date` 在两台机器上严格一致。**

## 联机前必须做到的两件事

1. **双方装同一份补丁** —— 同一个 zip、同一个 sha256。一边有一边没有 ⇒ **必然**不同步。
2. **双方 `render.ini` 的 AI 开关一致** —— 都 `ai=1`，别一个开一个关。

---

## 排错口径

| 现象 | 是什么 |
|---|---|
| **卡住 / 画面漂移** | 不同步 —— 检查双方补丁与开关 |
| **崩溃** | **不是**不同步。另按崩溃取证 |

## ⚠️ 诚实声明

**联机尚未实机对局验证。** 以上是**架构推理**，依据是：

- ✅ AI 随机走同步种子（源码证据）
- ✅ 唯一的墙钟依赖已换成游戏内日期
- ❓ **仍未知**：补丁会不会在某处间接影响 AI 的调用顺序 / 决策时间点

**⇒ 第一次联机建议先跑一局小地图。遇到卡住/漂移，把双方的 `update/sk2_zh.log` 一起发来。**
