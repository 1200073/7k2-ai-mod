# 汉化显示 bug：两类"少字"的根治

> 这一页记录 **7K2 HD 中文汉化**里最反直觉的两类显示 bug。
> 它们看起来都是"字没显示全"，但**根因完全不同，修法也完全不同**。
> 如果你在给老游戏做汉化（尤其 Big5 / GBK 双字节 + 位图字体），这一页大概率用得上。

---

## 0. 先分清：你遇到的是哪一类？

| | **A 类：恒定丢末字节** | **B 类：单字静默消失** |
|---|---|---|
| 缺在哪 | **永远是最后一个** | 可以在**中间**任意位置 |
| 缺多少 | 恒定 1 个字节（≈半个汉字） | 整个字（2 字节） |
| ASCII 受影响吗 | **不受影响** | 一样受影响 |
| 触发条件 | 任何中文字符串 | 该字**没进字体池** |
| 判据 | 数字/尾部字符被截，前面全对 | 缺的那个字全语料里**只出现过这一次** |
| 修法 | 把要保住的内容**前置** + 末尾放牺牲位 | **换字**（换成已在别处显示过的字） |

**⇒ 判据一句话：看缺的位置。尾部恒定 = A；中间随机 = B。**

---

## 1. A 类：中文字符串恒定丢最后一个字节

### 现象

魔族建筑的科技费用，英文原版正常，汉化后：

| 实际值 | 屏幕显示 |
|---|---|
| 600 | `60` |
| 1000 | `1,00` |
| 1400 | `1,40` |

**★ 关键线索：`1,00` 里那个千分位逗号还在。**

⇒ 说明**数值本身没错**（引擎算的是 1000），是**渲染时被截掉了最后 1 个字节**。
⇒ 如果算术错了，根本不会有逗号。

### 弯路（别重走）

| 尝试 | 结果 |
|---|---|
| 怀疑 `live_points_cost()` 算术（`complex_level * 20`） | ❌ 显示和扣费读的是同一个函数，不存在 ×10 |
| 怀疑缓冲区太小（`TEXT_RES_STRLEN = 255`） | ❌ 跟 255 差得远 |
| 怀疑装错目录（读到了英文原版） | ❌ 那个目录里 0 处中文 |
| **把标签缩短**（`所消耗生命點數﹕` → `生命點數﹕`） | **标签确实变短了，但数字照样被截** ❌ |

**⇒ 缩短标签这一轮很有价值**：它证明了**问题与"标签宽度"无关**。

### 根因

**中文字符串在某个转换/拷贝环节恒定丢最后一个字节。** 纯 ASCII 不受影响 —— 所以"英文原版正常、汉化后恒定少一位"。

### 修法（已验收）

**把要保住的内容挪到最前面，末尾留一个全角空格当"牺牲位"：**

```
改前：  [LARE]所消耗生命點數﹕%1d
改后：  [LARE]%1d 生命點數　        ← 数字前置；末尾那个「　」是 U+3000 全角空格
```

**原理**：恒定丢掉的那 1 个字节，去吃末尾那个没用的全角空格，正文就完整了。

**实机结果**：`600生命点数` / `1,000生命点数` / `1,400生命点数` —— 全部正确。

> ★ **通用做法**：凡是"数字/关键内容在尾部会被截"的格式串，一律改成
> **`%1d` 在前 + 正文在后 + 末尾一个全角空格**。这个模式在本项目里一次修好、没复发。

### 施工注意

`.res` 文本文件在本作里**没有容器头**，是纯 `[KEY]内容\r\n` ⇒ **改长度是完全安全的**。
（`STD.SET` 那种定长数据表不一样，见第 3 节。）

## 2. B 类：字体池静默丢字

### 现象

| 想显示 | 实际显示 | 丢的字 |
|---|---|---|
| 蜥蜴族 | `蜥族` | `蜴` |
| 飛鏢戰車 | `飞 车` | `鏢`（连带中间空一格） |
| 比瑪蜂巢 | `比蜂巢` | `瑪` |

**⇒ 不报错、不显示方块、不当成乱码 —— 直接当你没写。**

### 根因

游戏**没有全字库**。它的字形池是**按用到的字现建的**：
从没在游戏文本里出现过的字 ⇒ 池里没有这个字形 ⇒ 画不出来 ⇒ 静默跳过。

**⇒ 判定方法：把候选字丢进全语料 grep 一遍，出现次数为 0 的，就是高危字。**

```powershell
# 例：检查「蜴」在本作全部文本资源里出现过没有
'蜴' 编码后在全语料里 count == 0  ⇒  之前从没被用过  ⇒  池里没有  ⇒  别用
```

**三个实证全都符合这个判据**：`蜴` / `鏢` / `瑪` 在被我们引入之前，全语料出现次数都是 **0**。

### 修法：换字，别想着补字形

| 原字 | 换成 | 为什么安全 |
|---|---|---|
| `蜴` | `蜥` | `蜥` 已在「巨蜥巢穴」里正常显示 |
| `鏢` | `蛇` | `蛇` 已在「毒蛇戰車」里正常显示 |
| `瑪` | `魔` | `魔` 已在「魔族」里正常显示 |

**⇒ 位图字体池扩容是另一条工程线；换字几乎总是更便宜、更快。**

### 施工注意

**别照用户口述的字直接替换。** 他说「田比」，文件里其实是「**毗摩**」——
先按字形候选在文件里搜（`田比` 0 处 / `毗` 1 处 ⇒ 定位成功），别按读音猜。

## 3. `STD.SET` 是定长数据表：只能等长替换

名字类字段（族名、建筑名、单位名）在 `STD.SET` 里是**定长字段**（本作实测 **30 字节**）。

**⇒ 替换必须等长：新串不足就补空格，整文件字节数必须一字节不变。**

```python
# 正确做法示意
pad = b' ' * (len(old_bytes) - len(new_bytes))   # 变短才补空格
buf = buf.replace(old_bytes, new_bytes + pad)
assert len(buf) == original_length               # ★ 写完必核
```

**⇒ 每改一轮都核文件大小**。本例最终稳定在 `1,322,443 B`（与英文原版一字节不差）。

## 4. 译名以"老版本"为准，不要自己另译

本项目一度把魔族名字全换成了音译（`卡舒夫巢穴`、`布雷格馬巢穴`…），玩家反馈"根本不知道啥意思"。

**⇒ 找回老的台版（3DM 2.10c）一看：人家本来就是意译。**

```
老版： 綠妖巢穴 / 魔蟲巢穴 / 猛獸巢穴 / 牛頭巢穴 / 石怪巢穴 / 骷髏巢穴 / 巨蜥巢穴
新版： 卡舒夫巢穴 / 布雷格馬巢穴 / 克拉索斯巢穴 / ...
```

**⇒ 所以这不是"没翻过"，是**后来的版本退化成了音译**。**

### 教训

1. **做汉化修复前，先去翻有没有更老的官方/民间译文** —— 它往往比你自己拟的准
2. **但别过度推广**：本例里特色建筑名 / 单位名（`Lishorr` / `Vapngart` / `Keraal` / `Nemeze` / `Cobrez` / `Peltez`）**老版也保持英文**，那就没有权威译名 —— 这种时候要么问玩家，要么让玩家直接起名
3. **一个族名和它的巢穴名必须同一套口径**，否则会出现"族叫骨族、巢穴却叫埃茲皮內茲巢穴"的割裂

**★ 玩家给的解释往往比任何译名都准。** 本例里玩家直接说明了 `Nemeze` = 火炮车、
`Cobrez` = 飞镖战车、`Peltez` = 投石机 —— 而英文代码正好是 `F_CANNON` / `F__BALLI` / `F_CATAPU`，
完全印证。**他一句"这东西是干什么的"，胜过查半天词源。**

## 5. 收口检查清单

改完汉化后，按这个顺序核一遍：

- [ ] **整文件字节数**有没有变（`STD.SET` 必须不变）
- [ ] **音译残留复扫**：把改前所有旧串列出来逐个 count，必须全是 0
- [ ] **按表分扫**：同一个概念在不同表里可能是**两套不同的音译**（本例：巢穴表写「卡舒夫」、单位表写「卡爾舒夫」）⇒ 只扫一套会漏
- [ ] **新引入的每个字**，在全语料里 count 是多少？0 次 ⇒ 高危
- [ ] **备份文件**留着（`xxx.before-<改动名>`），随时可回退
- [ ] 实机验证：**改的是不是玩家真会看到的那个界面**

> ★ 最后一条吃过亏：曾有一次改完玩家说"还是不行"，结果查日志发现
> **那一局他根本没打开过那个面板**（新旧字符串的渲染计数都是 0）。
> **⇒ 用户报"还是老样子"时，先证明他走到了那个界面，再改代码。**
