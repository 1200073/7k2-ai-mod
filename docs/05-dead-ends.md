## 🚧 死路 1：让中立单位主动攻击（架构级互斥）

### 想做的事

中立巢穴（`nation_recno == 0`）里的兵，够多了就出去打附近的人。

### 为什么做不到

```c
// Unit::attack(short targetRecno, bool resetOrder) 第一行：
if( !set_attack(targetRecno, resetOrder) ) return;   // ★ 静默退出，零日志

// set_attack() 里的两道关卡：
int Unit::set_attack(short targetRecno, bool resetOrder)
{
    if( !can_attack() )                    return 0;   // 关卡一
    ...
    if( !validate_attack_target() )        return 0;   // 关卡二
}
```

**⇒ 中立单位没有 `Nation` 对象 ⇒ 没有外交关系 ⇒ 没有"敌对"状态 ⇒ 关卡二必然拒绝。**

**⇒ 表现：指令发出去了、日志显示"编入 N 个单位"、然后……什么都不发生。**

### 我们试遍了三条 API，全部静默失效

| 尝试 | 结果 |
|---|---|
| `unit_group.attack(objRecno, COMMAND_AI)` | ❌ 零反应 |
| 逐单位 `Unit::attack(objRecno, ...)` | ❌ 零反应 |
| 伪造 `base_obj_recno` | ❌ 同样无反应（而且 `+0x04` 这个偏移**后来验证是对的**） |

**⇒ 这不是"参数传错"，是"前置条件被拒"。**

### 唯一架构级解法（代价太大）

**给巢穴一个 Nation。** 但：

```c
#define MAX_NATION  7
```

7 个国家位，**玩家 + 人类 AI + 魔族 AI 全都在抢**。而且第 8 个国家会同时踩穿十几处数组（见死路 2）。

**⇒ 结论：要么接受"中立单位不会主动攻击"，要么付出"占一个对手位 + 可能的数据损坏"的代价。**

### 如果你的思路不一样，欢迎开 Issue

我们可能漏了什么。特别是：**有没有办法在不给 Nation 的前提下，让 `validate_attack_target()` 通过？**

## 🚧 死路 2：加第 8 个国家位

### 想做的事

`MAX_NATION` 是编译期常量 `7`，加到 8 不就多一个位？

### 为什么做不到

**数据层其实装得下**（`nation_array` 是 `DynArrayB`，会自动扩容；`nation_recno` 存 `char`，能到 127）。

**但有一堆"按国家号直接下标"的定长数组**：

| 位置 | 数组 | 被写坏的是什么 |
|---|---|---|
| `onationb.h` | `relation_array[MAX_NATION]` 等 4 个 | ★★★ **Nation 对象内部的相邻成员** |
| `ofirmres.h` | `nation_firm_count_array` / `nation_tech_level_array` | 建筑资源表 |
| `oregions.h` | 共 8 个 `[MAX_NATION]` 数组 | 区域统计 |
| `otown.h` | `resistance_array` / `target_resistance_array` | 城镇数据 |
| `ogodres.h` | `nation_know_array` / `prayer_count` | 神祇数据 |
| `ounitres.h` | 3 个统计数组 | 单位资源表 |
| `onationa.h` | `nation_color_array[MAX_NATION+1]` | 颜色（**这个才是"看得见"的那个**） |

### 最致命的那一条

```c
// onationb.h:351
NationRelation* get_relation(int nationRecno) {
    return relation_array + nationRecno - 1;    // ★★★ 纯指针算术，零边界检查
}
```

- `get_relation(8)` = `relation_array + 7` ⇒ **稳稳越界一整个 `NationRelation` 结构体**
- 而它是**全游戏最高频的调用之一**（外交、宣战、AI 判断、通行权……）
- **⇒ 第 8 个国家一参与任何外交，就往 Nation 相邻成员上写数据**

### 为什么这比"崩溃"更可怕

| 崩溃 | 越界写 |
|---|---|
| 立刻中断，你知道出事了 | **不崩，状态悄悄变坏** |
| 有异常码 + 偏移量可查 | 可能几百回合后才发作 |
| 能定位 | 症状像"AI 变傻""忠诚乱跳""科技乱升" ⇒ **查不出源头** |

**⇒ `MAX_NATION = 7` 不是"配色的限制"，是"整套数据结构的形状"。**

**⇒ 插件只能改代码逻辑，改不了全局变量的大小和相对位置。这条路物理上封死。**

## 🚧 死路 3：`patrol()` 出来的兵没有"归宿"就消失

### 我们做到的

`FirmCamp::patrol(0)` = `0x00478160` **能安全调用于中立巢穴**，兵真的会出来。

```
[AI] ★ 出巢：兵 15->0  地图单位 160->166
[AI] ★★ 已下令攻击目标#254 @(386,184)：编入 16 个单位
```

**⇒ 日志证明：30 个兵一个不少全出来了。**

### 但他们会消失

**引擎规则（由玩家的实战经验反推出来的）：**

> **出巢的单位必须始终有一个"归宿"（家 / 持续性指令 / 编队归属）。归宿一失效，单位被回收。**

**证据来自玩家的回忆：**

> "早年的战术：派一个兵打一下中立巢穴，把守军引出来，然后跑；
> 快速把巢穴买下 —— 那些跑出去的兵回来发现家没了，**就消失了**。"

### 我们试过绕过

| 尝试 | 结果 |
|---|---|
| `assign(x, y)` 移动到坐标 | ✅ 真的会走 —— 但**到达终点后没有新归宿 ⇒ 被回收** |
| 在到达前**每 18 秒换一个巡逻航点** | ❌ 仍然整批消失 |
| 出巢后立刻 `attack` | ❌ 见死路 1（攻击被拒） |

**⇒ `assign` 只在"移动期间"算归宿。想让它一直活着，就得一直有指令 —— 但我们没能稳定做到。**

### 如果你要继续这条线，请从这里开始

**不要猜机制，先量：**

1. 每 1~2 秒遍历一次 `unit_array`，记录那批单位的 `unit_mode` / 坐标 / 是否还在
2. 判据：**第几秒消失**、消失时**在哪**（巢穴？半路？航点？）、消失前一刻**有没有指令**
3. 有了"消失时刻 + 位置"再谈机制

**我们就是因为没先量，盲试了 5 轮。**

## 🚧 死路 4：自己写"出去/召回"逻辑

### 想做的事

让巢穴的兵出去兜一圈再回来 —— 自己写个计时器。

### 为什么不该写

**引擎早就有这套闭环了** —— 玩家亲眼见过：

> "打巢穴的时候，兵会跑出来追着我的部队跑，**跑出一定距离就自己回去了**。"

**⇒ 出巢、追敌、跑远归位，全是原版自带的。**

**⇒ 正确做法是"触发它"，而不是"重新实现它"。**

### 我们走了弯路

先花了好几轮写"120 秒后召回"的计时器，然后才从玩家的一句话里发现原版已有。
**⇒ 教训：给"自主行动"加功能时，先问"宿主是不是已经会自己结束/回来"。**

（顺带：那句"兵跑远就回去"最后确认**不是** `patrol()` 干的 —— `patrol()` 的四个调用者全在**进攻侧**，
防守必然是另一个函数，**至今没定位到**。）

## 🚧 死路 5：用"计数器增量"判断发生了什么

### 我们犯了三次

| 次 | 我当时说的 | 真相 |
|---|---|---|
| 1 | "崩在 Array 访问器的调用契约上" | 真凶＝`unit_array` 基址错 4 字节 |
| 2 | "兵生成后缺归宿被回收" | 当时误判成"真的丢兵" |
| 3 | "★★★定案：真丢兵" | 源码说失败不删兵；编组证明 30 个兵都在 |

### 共同的错

**用一个"看起来在数同一样东西"的量做判据，却没先读产生它的代码。**

**具体到 `unit_array.count`：**

```
它 = "最高已用编号"，不是"存活数量"
删除后槽位会被复用 ⇒ 新建 15 个单位，count 可能一点不涨
```

**⇒ `160 -> 160` 不代表"一个都没生成"。**

### 新纪律

**任何"X 没涨 / X 没变 ⇒ 没发生"的推论，先回答三个问题：**

1. **X 的定义是什么？**
2. **谁写的 X？**
3. **会不会复用 / 清空？**

## 🚧 死路 6：以为"换个 API 就行"

**同一个功能试了三个函数，都是"零反应"，就该停下来想：**

**⇒ 不是实现问题，是**前置条件被拒**。**

**正确动作：去读被调函数的**第一行**，找 `if(!xxx()) return;` 这类静默闸门。**

**我们连着两轮把"静默失败"当成"参数传错"，白烧了两次编译和两次读档。**

## 🚧 死路 7：日期格式串里的中文

### 现象

游戏内日期显示成 `月 7, 100`（应为 `7月 7, 1002`），**首尾各丢一个字符**。

### 试过且失败

| 做法 | 结果 |
|---|---|
| 改格式串内容 | ❌ 还是丢 |
| 首尾加空格当"祭品" | ❌ 空格没替它挨刀 |
| 改渲染宽度 | ❌ 无变化 |

### 真相

**那个绘制路径遇到 CJK 字符就会吞字。**

**⇒ 换成纯 ASCII（`1002.5.28`）立刻正常。**

### 还有个格式码的坑

`%N,cd` 里**逗号后面那位是"数字风格"，不是"宽度"**：

| 写法 | 输出 | 含义 |
|---|---|---|
| `%3d` | `1,002` | 默认，**带千分位逗号** |
| `%3,4d` | `1002` | 风格 4 = 纯数字 |
| `%2,2d` | `$5` | **风格 2 = 货币**（会加 `$`） |

**⇒ 我按"宽度 2 补零"去猜，结果盘上变成 `1002/$5/$29`。**

### 最终方案

```
状态栏（长格式）: %3d年%2d月%1d日   →  1002年4月12日
右上角（短格式）: %3,4d/%2d/%1d     →  1002/5/29
```

**代价：月/日不补零。补零的风格号没找到，别再盲猜。**

## 小结：这 8 条背后的通用规律

| 教训 | 一句话 |
|---|---|
| **静默失败 ≠ 参数错** | 先读被调函数的第一行 |
| **计数器 ≠ 产量** | 读生产方自己记的句柄列表 |
| **先量再改** | 没有客观锚点就别动手 |
| **宿主可能已经有答案** | 先问"它是不是本来就会" |
| **编译期常量是物理墙** | 插件改不了数据结构布局 |
| **同一条路连错两次就停** | 换方向，别加深 |
